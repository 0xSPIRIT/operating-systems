OS Chapter 2
============

Operating System Services:
  - UI
  - Program execution
  - I/O operations
  - File-system manipulation
  - Communication (IPC / network)
  - Error detection
  - Resource allocation (CPU cycles, main memory, file storage, I/O devices)
  - Logging
  - Protection & Security

System call:
  - Programming interface to the services provided by the OS
  - Written in C/C++
  - Accessed by programs via an API
  - Eg. Win32 API, POSIX API, Java API
  - Parameters may be stored in regsiters
  - If there are more parameters than registers, the parameters
    would be stored in a buffer and the register will point to
    the buffer

Applications:
  - Programs compiled on one system are not usually
    executable on other OS's, even though they might
    share the same CPU architecture.
  - Each OS has their own system calls, format etc.
  - Java, Python, Ruby are interpreted languages

ABI:
  - Application Binary Interface, defines how different
    components of binary code can interacts.
  - Basically the lower level details of an API.
  - Calling conventions (how parameters are passed to functions)
  - Register usage
  - Stack layout
  - System call interface

System boot:
  - Bootstrap loader, BIOS, stored in ROM or EEPROM locates the
    kernel and loads it into memory and begins executing the code.
  - Modern systems replace BIOS with EUFI (Unified Extensible Firmware Interface)
  - GRUB; allows selection of kernel from multiple versions / disks

Errors:
  - Core dumps capture the memory of a process at the point of failure
  - Log files generated by OS
  - OS failure generates Crash dump containing kernel memory
  - Profiling
